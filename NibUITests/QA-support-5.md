## S - native selection

The seven named rich-text tests reach native Command-A, then fail Cut/Copy availability with unchanged editor text; CopyText's dump exposes the Text box and input assistant, matching round 4 R's lost selection diagnosis. The screenshot of TextSelectedRange shows the caret and typed text, not a selected range. verifyNativeSelection now first checks native Cut/Copy, then double-taps the editor and waits at most two seconds for native Select All; if absent it collapses the word selection and long-presses once, with another two-second bound. It must actually tap Select All on the fallback path before accepting Cut/Copy, so merely double-selecting one word cannot satisfy the fallback. Object cmd.clipboard actions remain excluded. Exact text and focus checks remain, as do every caller's rich-text/range assertions. No clipboard, deletion, undo or text replacement is used for selection verification.
