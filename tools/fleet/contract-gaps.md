# Contract gaps reported by feature agents

Each agent worked around these inside its own files. Resolve them in NibContracts during integration (update CONTRACTS.md, bump the contracts tag), then remove the per-feature workarounds.

Known blocker: F031 is red because DocTransaction.revert does not undo an item move made in the same step as an attach (FeatShapesTests.testDroppingAnItemIntoAShapeAttachesItInTheSameUndoStep). Fixed in contracts-v2 (G4); ContractsV2Tests.testAttachAfterMoveInTheSameGroupUndoesTheMoveToo reproduces it.

**contracts-v2 triage (branch v2/contracts).** Every gap line ends with its resolution: `[v2: G<n> <API>]` = resolved by the contracts-v2 API of group G<n> (docs/CONTRACTS.md › "contracts-v2 changelog" lists the exact signatures and the workaround sites to remove), `[v2: rejected - reason]`, or `[v2: deferred - reason]`. Lines marked "(reported during the v2 pass)" came from fix agents after this file was collected. Totals for the 368 original lines: 220 resolved, 67 rejected, 81 deferred (33 NibDesign, 12 catalogue rows in forge-spec, 11 app shell, 25 other owners or later design); the 21 v2-pass lines: 19 resolved, 2 deferred.

**Spec pass (branch v2/spec).** Lines the spec owner acted on also end with `[v2/spec: …]`: the catalogue rows and additive params now in docs/forge-spec.json and ARCHITECTURE §6.5 (the feature tables mirror the "Commands owned" lists; nothing generates them), or the sentence added to an unbuilt feature's spec. Deferred lines owned by built features (renderer, store, recognition inputs, app shell) are left to their fix passes.

## F001
- No contract type exists for the 'store.readOnly' flag. It is published with services.set as an NSMutableSet of DocumentID.raw strings. Consumers such as F070 and F042 read it with services.get("store.readOnly", as: NSSet.self)?.contains(doc.raw). A typed ServiceKeys constant or a DocumentPersistence.isReadOnly(doc) requirement would be cleaner. [v2: G2 DocumentPersistence.isReadOnly(_:), CommandContext.isReadOnly(_:), NibApp.isReadOnly(_:), ServiceKeys.storeReadOnly]
- DocumentPersistence.didChange and flush cannot throw. The format-gate refusal is logged, and write or WAL failures are reported as sync.status events. AssetStore.put throws NibError(.unsupported) for read-only documents. fileURL throws it only when it would have to create a folder in a read-only package. [v2: rejected - by design: persistence reports write failures as sync.status events (now typed, SyncStatusPayload); throwing from didChange would undo committed edits]
- The contracts do not define a sync.status payload shape. The store emits {state: warning|error, source: "store", reason: newerFormat|futureRevision|unreadable|writeFailed|walFailed, message, files?}. F025 and F070 should agree on this or on a shared schema. [v2: G3 SyncStatusPayload (sync.status)] [v2/spec: F025 and F070's spec says so (SyncStatusPayload)]
- <dev> comes from String(format: "%08x", app.clock.device). In the app that equals DeviceIdentity.hex, because NibApp defaults deviceID to DeviceIdentity.current. It also gives Harness(deviceID:) two-device tests distinct files. No contract accessor for 'this app's device hex' exists. [v2: G19 NibApp.deviceHex / HLCClock.deviceHex]
- Harness puts InMemoryPersistence and InMemoryAssetStore back after register, so other features cannot reach the real store through Harness. PackagePersistence is internal. For F025's two-persistence acceptance test, call NibStoreFeature.register(harness.app) again after Harness init to install the real store. The package locator must point at a temp folder, which the Harness InMemoryLibrary already fills. [v2: G20 Harness(keepFeatureServices: true)]
- Deadlock hazard across features: flush() runs an NSFileCoordinator write synchronously from the main actor via io.sync. An in-process NSFilePresenter (F025) that uses OperationQueue.main as its presentedItemOperationQueue and implements relinquishPresentedItem(toWriter:) would deadlock. Presenters must use a background queue. [v2: rejected - a rule for F025, not a contract type: NSFilePresenters use a background presentedItemOperationQueue (recorded in the changelog)] [v2/spec: F025's spec says so]
- (reported during the v2 pass) Stroke points decode through JSONDecoder dominates page loads; a fast path for the encoder's own layout would let PageReader drop its decoder. [v2: G5 Stroke.unpackFull(_:) / Stroke.unpackCompact(_:)]

## F003
- DocTransaction.put stamps createdBy = principal on any record new to a page. So when a non-user principal runs node.move to take an item across pages (tombstone plus insert with the same id), the original provenance cannot be kept on the target page. No contract API writes a moved record with its existing createdBy. For user moves createdBy is preserved. [v2: G5 DocTransaction.move(item:doc:from:to:transform:z:), put(_:doc:page:keepingProvenanceFrom:in:)]
- CommandContext does not expose the NibApp. query.context needs ui.activeNavigator for open tabs and custom-item text needs content.customItemTypes. Workaround inside FeatQuery: use NibApp.shared only when its bus === ctx.bus. Otherwise tabs fall back to [session.document] and custom text falls back to data.title/data.text. [v2: G1 CommandContext.app / .content / .ui / .navigator (tabs: ctx.navigator?.openDocuments; custom text: ctx.content.customItemTypes)]
- The catalogue lists query.get {ref, depth?, fields?, points?} and query.tree {root?, depth?} with no cursor, but the 20 KB cap (§7.4 and the acceptance test) needs one to page. Added an optional `cursor` param to both (additive). It pages items, children, tree rows and stroke points. [v2: G21 §6.1 cursor paging convention; ToolCatalog nib_get gains `cursor`]
- Gateway.isLocked defaults to false until F071 wires it. F003 checks services.lock itself: non-user reads of a locked document return {ref, locked: true}, and writes throw `locked`. [v2: rejected - intended: F071 wires Gateway.isLocked; checking services.lock in reads is §15.8]
- DocTransaction.put(_ item:doc:page:) stamps the caller as createdBy whenever the item is new on that page. So when the AI or a plugin moves an item to another page with node.move, the item is re-attributed to that principal (for example the user's handwriting becomes 'ai:<chat>'). Fixing this needs a contract change such as put(_:doc:page:keepingProvenanceOf:) or a DocTransaction move helper. For now the limitation is documented in the node.move summary and in a ponytail comment in NodeCommands.swift. [v2: G5 DocTransaction.move(item:doc:from:to:transform:z:), put(_:doc:page:keepingProvenanceFrom:in:)]
- CommandContext.inputFile uses `case "https", "http" where principal.isUser`. In Swift the where clause applies only to the last pattern, so any non-user principal can make https downloads. It also never checks the network scope and never limits size. F003 works around this in AssetBytes.load: plugins need .network for http(s) urls, 'tmp:' names are validated, and files over 200 MB are rejected. Other url-taking commands still depend on inputFile, so the check belongs there. [v2: G6 CommandContext.inputFile fixed (https + network scope + plugin network.hosts, NibLimits.maxDownloadBytes, tmp: names)]

## F004
- Infinite boards: TemplateDefinition has no repeat period, so a template can't say how to line up across tiles. Workaround: board templates are laid out on a 240 pt-aligned grid, which fits spacings of 24/20/30/40/48/60/80/120. A spacing that does not divide 240 would shift at the seams. [v2: G7 TemplateDefinition.metricsProvider / TemplateMetrics.repeatPeriod, renderRegion]
- No page-level content revision. The thumbnail key (doc/page/max rev) is the highest rev of the page record and all its items, including tombstones. That means loading the page's items into the Workspace just to check whether a disk thumbnail is still valid. Large libraries would benefit from a per-page content rev in PageRecord or the persistence layer. [v2: G9 DocumentPersistence.contentRevision(_:page:), Workspace.contentRevision(_:page:)]
- PageRecord.rotation semantics are not specified (does rotating swap the size or rotate items?). Workaround: the renderer turns only PDF and image backgrounds clockwise by the rotation, aspect-fitted to the page. Items are drawn as stored, since geometry is baked. [v2: G22 PageRecord.rotation pinned + PageRecord.backgroundTransform(sourceSize:)]
- No per-page signal when a template or drawer registration changes (plugin installed or removed). Workaround: the renderer watches .nibRegistryDidChange on content.drawers and content.templates and drops every tile and in-memory thumbnail. Disk thumbnails are keyed by rev, so they stay stale until the page next changes. [v2: G11 RegistryChange userInfo (ids, kind, generation), Registry.generation]
- Replay for items drawn by drawers (e.g. stroke.tape): the renderer applies spotlight and reveal itself only to pen, pencil and highlighter strokes. Drawer-drawn items get DrawContext.replay and must handle it themselves (the contract does not require it). [v2: rejected - intended: DrawContext.replay is the contract; drawers of ink-like items honour it themselves]
- The .nibRegistryDidChange notification fires for every drawer and template registration, including the ones features make at launch after the renderer is installed. The renderer can't tell those launch registrations apart from later plugin or content-pack changes. So the review's suggestion to wipe the disk preview folder on a registry change would empty the thumbnail cache at every launch. Instead, a render is not saved to disk if its template or an item drawer is missing, or if the page changed while it rendered. Not covered: a drawer that is replaced later but was present when the thumbnail was saved. [v2: G11 NibApp.isStarted + RegistryChange ids]

## F005
- CommandContext cannot reach app.content (ContentRegistries), so commands had no way to look up templates. Workaround: in register(), NibTemplatesFeature publishes app.content.templates as the services extra 'templates.registry' (TemplateCommands.registryKey). Commands throw `unavailable` if it is missing. [v2: G1 CommandContext.app / .content / .ui / .navigator]
- TemplateDefinition.render(params, size, scale) has no visible-rect input, so templates build ops for the whole page. At deep zoom on a large page, the fading half-spacing whiteboard dot layer is skipped once it would exceed 100k dots (WhiteboardGrids.fineDotBudget, marked with a ponytail comment). Drawing.swift's dots/hlines loops also cover the whole op rect. A render-region parameter would lift both limits. [v2: G7 TemplateDefinition.renderRegion + renderOps(_:size:scale:region:)]
- DocTransaction.revert skips a record written twice in one undo group (after the first revert its rev no longer matches), so one command writing the same record twice would not undo fully. Worked around by writing each page and each DocumentMeta at most once per command (TemplateCommands.MetaChange / apply). Other features that write the same record twice in one group will hit this. [v2: G4 DocTransaction.revert rebasing (same group and consecutive entries)]
- The cover state is only DocumentMeta.coverEnabled. page.setBackground cannot tell a custom PDF/image cover (F045) from paper, so it only ever turns coverEnabled on. page.setTemplate turns it off when a cover template on page 1 is replaced by a paper template. [v2: deferred - F045 (unbuilt) defines custom covers; revisit the cover flag with it] [v2/spec: F045's spec now makes it define the custom-cover marker]
- DisplayOp text has no alignment or weight, so template labels (planner headings, weekday names, day numbers) are left-aligned in the default system weight. [v2: G8 DisplayOp.align / DisplayOp.weight (DisplayFontWeight)]
- For infinite boards (size == nil) the contract does not say what size F004 passes to render. Whiteboard lattices are anchored at the origin of the given size, so F004 must pass a world-aligned rect for grids to line up across tiles. [v2: G7 TemplateDefinition.render doc: patterns anchored at page origin; boards call renderRegion with world rects]
- NibContracts Workspace keeps its page cache (pageItems) private and has no public way to ask which pages are cached. So itemsOutside cannot tell which pages were cached before the check. As a workaround it evicts every checked page that no EditorSession is showing, using workspace.evictPages(doc, keeping: all pages minus that one). Data is safe because evictPages flushes first, and the page reloads when it is next needed. A cached neighbour page that is off-screen may be reloaded later. A small public accessor on Workspace, such as isPageCached(doc, page) or cachedPages(doc), would let us keep pages that were already cached. [v2: G10 Workspace.isPageCached(_:page:) / cachedPages(_:)]
- The GitHub Actions run for this branch only runs the 'feature' job (build and NibTemplatesTests). The 'test' and 'ipa' jobs were skipped, so the full suite and the conformance run on main have not been checked with this branch. [v2: rejected - CI process note, not a contract gap]

## F010
- The contracts cannot tell a tool when the dry tiles for newly committed items are on screen. The eraser keeps its preview for about 150 ms after ink.erase commits and then clears it and unhides. This is the same hand-off problem wet ink has (EraserTool.commit). [v2: G14 CanvasHost.afterNextRender(page:_:)]
- CanvasTool.isSticky has no 'tool finished' signal. F016 would switch back to the previous tool without knowing when an erase finished, and a second switch could bounce back to the eraser. So the eraser always reports itself sticky and does Auto-deselect itself on lift through tool.select. [v2: G15 CanvasHost.finishToolUse(_:) / EditorSession.finishToolUse(sticky:)]
- The ink.erase catalogue row has no layer parameter, so the command uses ctx.activeSession?.activeLayer ?? 0, as the spec asks. An AI or bridge call with no window open erases on layer 0. [v2: rejected - intended: commands default the layer to ctx.activeSession?.activeLayer ?? 0 (§6.1)]
- CanvasHost cannot convert a sample from one page to another. An eraser gesture stays on the page it started on, and samples that land on other pages are ignored. [v2: G14 CanvasHost.convert(_:from:to:)]
- NibStrokeWidthSlider is fixed to millimetres and a 'Thickness' label, so it does not fit an eraser measured in on-screen points. The size presets were built from NibColor, NibMetrics and NibPressStyle tokens. DESIGN.md asks for a 'destructive plain button', but NibButton has no such kind, so Clear Page uses NibButton .destructive. [v2: deferred - NibDesign owns tokens, glyphs and components (design-system passes on v2/dstokens, v2/glass, v2/physics)]
- Dictionary(key:default:) cannot be used as a key path because of its autoclosure, so the sheet's switches bind to a Set through a small internal Set subscript(member:) extension in EraserSettingsView.swift. [v2: rejected - Swift language limitation, not a contract gap]
- CanvasHost has no signal for when the renderer has drawn committed ink. So after its single ink.erase, EraserTool keeps its preview and hidden set for about 150 ms, then unhides. This avoids a flicker. A 'didRender(page:)' callback would replace the fixed delay. [v2: G14 CanvasHost.afterNextRender(page:_:)]
- CanvasHost.setHidden can only hide whole items. While dragging, a cut stroke is hidden and what is left of it is redrawn in the tool overlay as a CAShapeLayer polyline (stroke colour, mid-point nib width, multiply blend for highlighter). There is no PencilKit ink look in that preview. A 'preview partial stroke' host API would make it exact. [v2: deferred - needs a stroke-preview API from the canvas/renderer (F006/F101/F004)] [v2/spec: F101's spec lists it as a deferred canvas gap it owns]
- CanvasTool has no 'return to previous tool on lift' hook separate from isSticky. The eraser reports itself sticky and, when Auto-Deselect is on, runs tool.select with session.previousTool itself after the commit. That avoids a double bounce. [v2: G15 CanvasHost.finishToolUse(_:) / EditorSession.finishToolUse(sticky:)]
- The Delete Specific Items entry in the More menu opens the sheet through panel.open, which F017 owns. If F017 is disabled, that menu item fails with 'unavailable'. [v2: rejected - intended: a missing optional feature is an `unavailable` optional dependency (§6.2)]
- There is no query-API call for a synchronous snapshot of a page's items at touch-down. EraserTool reads app.workspace.items(doc, page:) directly for the live preview. The commit still goes through the ink.erase command. [v2: rejected - Workspace reads are public main-actor API; UI may read (writes go through commands)]
- DocTransaction has no bulk or indexed tombstone. The fix now tombstones the items it already fetched, so tx.delete no longer does a second lookup. But tx.put still scans the page linearly (currentItem and writeItem), so page.clear, page.deleteItems and remove() stay quadratic on boards near NibLimits.boardItemLimit. The review asked for docs/contract-requests/F010-bulk-tombstone.md, but that path is not one of F010's files, so it was not written. The request is recorded here and in a ponytail comment in EraseSupport.remove. [v2: G5 DocTransaction.delete(items:doc:page:), put(_ items:doc:page:), O(1) Workspace item index]
- No spatial index is available to features. Stroke bounds are still computed point by point when the EraseSession is built. Touch-down now skips items outside session.visibleRect on the current page and computes bounds once per eligible item, but a real fix needs an indexed Workspace.items(in:). [v2: deferred - a spatial index needs a per-page R-tree owned by the canvas/renderer (F004/F101); batch writes and the id index land in v2] [v2/spec: F101's spec lists it as a deferred canvas gap it owns]

## F012
- The iOS 26 Liquid Glass `.droplet(style: .handle)` is SwiftUI-only and lives in the window's NibDropletContainer. A CanvasAttachment has no way to put a droplet on the canvas, so the handles are rigid CALayer beads drawn with NibDesign water tokens: Clear corners and rotation bead (clearBodyOnPaper or chromeOpaque, waterLine, CALayer.nibElevation(.rest)) and Tinted edges (accent, tintRim). Status event "bridge.status", emitted on app.events. Token rotation goes through bridge.setEnabled {enabled: true, rotateToken: true}. The contracts have no shared constants for any of these. [v2: G27 BridgeNames, NibEventType.bridgeStatus] [v2/spec: F091's spec says so (BridgeNames)]
- The bridge's confirmation deadline (unanswered confirmations for .bridge principals are denied after 115 s, so no request waits more than 120 s) works by wrapping app.gateway.presenter in register(). This only holds if no later feature replaces gateway.presenter without delegating to the one it replaces. The contracts have no per-principal confirmation-timeout hook. [v2: G27 Gateway.setPresenter(_:forPrincipalKind:)]
- Gateway.policy has no per-principal registration API. The bridge chains onto the existing closure so that .bridge principals follow NibSettings.bridgeConfirmationPolicy. A feature that later overwrites gateway.policy without chaining would drop that. [v2: G27 Gateway.setPolicy(forPrincipalKind:_:)]
- The 'ai.directTools' setting (F084) is read untyped with settings.json("ai.directTools"). When it is absent, the bridge uses the default direct-tool list from AI.md §4, copied into MCPHandler.defaultDirectTools. The contracts do not export that default list. [v2: G27 NibSettings.defaultAIDirectTools / aiDirectToolsName] [v2/spec: F084 and F086's spec says so]
