# Contract gaps reported by feature agents

Each agent worked around these inside its own files. Resolve them in NibContracts during integration (update CONTRACTS.md, bump the contracts tag), then remove the per-feature workarounds.

Known blocker: F031 is red because DocTransaction.revert does not undo an item move made in the same step as an attach (FeatShapesTests.testDroppingAnItemIntoAShapeAttachesItInTheSameUndoStep).

## F001
- No contract type exists for the 'store.readOnly' flag. It is published with services.set as an NSMutableSet of DocumentID.raw strings. Consumers such as F070 and F042 read it with services.get("store.readOnly", as: NSSet.self)?.contains(doc.raw). A typed ServiceKeys constant or a DocumentPersistence.isReadOnly(doc) requirement would be cleaner.
- DocumentPersistence.didChange and flush cannot throw. The format-gate refusal is logged, and write or WAL failures are reported as sync.status events. AssetStore.put throws NibError(.unsupported) for read-only documents. fileURL throws it only when it would have to create a folder in a read-only package.
- The contracts do not define a sync.status payload shape. The store emits {state: warning|error, source: "store", reason: newerFormat|futureRevision|unreadable|writeFailed|walFailed, message, files?}. F025 and F070 should agree on this or on a shared schema.
- <dev> comes from String(format: "%08x", app.clock.device). In the app that equals DeviceIdentity.hex, because NibApp defaults deviceID to DeviceIdentity.current. It also gives Harness(deviceID:) two-device tests distinct files. No contract accessor for 'this app's device hex' exists.
- Harness puts InMemoryPersistence and InMemoryAssetStore back after register, so other features cannot reach the real store through Harness. PackagePersistence is internal. For F025's two-persistence acceptance test, call NibStoreFeature.register(harness.app) again after Harness init to install the real store. The package locator must point at a temp folder, which the Harness InMemoryLibrary already fills.
- Deadlock hazard across features: flush() runs an NSFileCoordinator write synchronously from the main actor via io.sync. An in-process NSFilePresenter (F025) that uses OperationQueue.main as its presentedItemOperationQueue and implements relinquishPresentedItem(toWriter:) would deadlock. Presenters must use a background queue.

## F003
- DocTransaction.put stamps createdBy = principal on any record new to a page. So when a non-user principal runs node.move to take an item across pages (tombstone plus insert with the same id), the original provenance cannot be kept on the target page. No contract API writes a moved record with its existing createdBy. For user moves createdBy is preserved.
- CommandContext does not expose the NibApp. query.context needs ui.activeNavigator for open tabs and custom-item text needs content.customItemTypes. Workaround inside FeatQuery: use NibApp.shared only when its bus === ctx.bus. Otherwise tabs fall back to [session.document] and custom text falls back to data.title/data.text.
- The catalogue lists query.get {ref, depth?, fields?, points?} and query.tree {root?, depth?} with no cursor, but the 20 KB cap (§7.4 and the acceptance test) needs one to page. Added an optional `cursor` param to both (additive). It pages items, children, tree rows and stroke points.
- Gateway.isLocked defaults to false until F071 wires it. F003 checks services.lock itself: non-user reads of a locked document return {ref, locked: true}, and writes throw `locked`.
- DocTransaction.put(_ item:doc:page:) stamps the caller as createdBy whenever the item is new on that page. So when the AI or a plugin moves an item to another page with node.move, the item is re-attributed to that principal (for example the user's handwriting becomes 'ai:<chat>'). Fixing this needs a contract change such as put(_:doc:page:keepingProvenanceOf:) or a DocTransaction move helper. For now the limitation is documented in the node.move summary and in a ponytail comment in NodeCommands.swift.
- CommandContext.inputFile uses `case "https", "http" where principal.isUser`. In Swift the where clause applies only to the last pattern, so any non-user principal can make https downloads. It also never checks the network scope and never limits size. F003 works around this in AssetBytes.load: plugins need .network for http(s) urls, 'tmp:' names are validated, and files over 200 MB are rejected. Other url-taking commands still depend on inputFile, so the check belongs there.

## F004
- Infinite boards: TemplateDefinition has no repeat period, so a template can't say how to line up across tiles. Workaround: board templates are laid out on a 240 pt-aligned grid, which fits spacings of 24/20/30/40/48/60/80/120. A spacing that does not divide 240 would shift at the seams.
- No page-level content revision. The thumbnail key (doc/page/max rev) is the highest rev of the page record and all its items, including tombstones. That means loading the page's items into the Workspace just to check whether a disk thumbnail is still valid. Large libraries would benefit from a per-page content rev in PageRecord or the persistence layer.
- PageRecord.rotation semantics are not specified (does rotating swap the size or rotate items?). Workaround: the renderer turns only PDF and image backgrounds clockwise by the rotation, aspect-fitted to the page. Items are drawn as stored, since geometry is baked.
- No per-page signal when a template or drawer registration changes (plugin installed or removed). Workaround: the renderer watches .nibRegistryDidChange on content.drawers and content.templates and drops every tile and in-memory thumbnail. Disk thumbnails are keyed by rev, so they stay stale until the page next changes.
- Replay for items drawn by drawers (e.g. stroke.tape): the renderer applies spotlight and reveal itself only to pen, pencil and highlighter strokes. Drawer-drawn items get DrawContext.replay and must handle it themselves (the contract does not require it).
- The .nibRegistryDidChange notification fires for every drawer and template registration, including the ones features make at launch after the renderer is installed. The renderer can't tell those launch registrations apart from later plugin or content-pack changes. So the review's suggestion to wipe the disk preview folder on a registry change would empty the thumbnail cache at every launch. Instead, a render is not saved to disk if its template or an item drawer is missing, or if the page changed while it rendered. Not covered: a drawer that is replaced later but was present when the thumbnail was saved.

## F005
- CommandContext cannot reach app.content (ContentRegistries), so commands had no way to look up templates. Workaround: in register(), NibTemplatesFeature publishes app.content.templates as the services extra 'templates.registry' (TemplateCommands.registryKey). Commands throw `unavailable` if it is missing.
- TemplateDefinition.render(params, size, scale) has no visible-rect input, so templates build ops for the whole page. At deep zoom on a large page, the fading half-spacing whiteboard dot layer is skipped once it would exceed 100k dots (WhiteboardGrids.fineDotBudget, marked with a ponytail comment). Drawing.swift's dots/hlines loops also cover the whole op rect. A render-region parameter would lift both limits.
- DocTransaction.revert skips a record written twice in one undo group (after the first revert its rev no longer matches), so one command writing the same record twice would not undo fully. Worked around by writing each page and each DocumentMeta at most once per command (TemplateCommands.MetaChange / apply). Other features that write the same record twice in one group will hit this.
- The cover state is only DocumentMeta.coverEnabled. page.setBackground cannot tell a custom PDF/image cover (F045) from paper, so it only ever turns coverEnabled on. page.setTemplate turns it off when a cover template on page 1 is replaced by a paper template.
- DisplayOp text has no alignment or weight, so template labels (planner headings, weekday names, day numbers) are left-aligned in the default system weight.
- For infinite boards (size == nil) the contract does not say what size F004 passes to render. Whiteboard lattices are anchored at the origin of the given size, so F004 must pass a world-aligned rect for grids to line up across tiles.
- NibContracts Workspace keeps its page cache (pageItems) private and has no public way to ask which pages are cached. So itemsOutside cannot tell which pages were cached before the check. As a workaround it evicts every checked page that no EditorSession is showing, using workspace.evictPages(doc, keeping: all pages minus that one). Data is safe because evictPages flushes first, and the page reloads when it is next needed. A cached neighbour page that is off-screen may be reloaded later. A small public accessor on Workspace, such as isPageCached(doc, page) or cachedPages(doc), would let us keep pages that were already cached.
- The GitHub Actions run for this branch only runs the 'feature' job (build and NibTemplatesTests). The 'test' and 'ipa' jobs were skipped, so the full suite and the conformance run on main have not been checked with this branch.

## F008
- NibSymbol has no tokens for an eyedropper or a colour-picker glyph. Worked around with NibSymbol(systemName: "eyedropper") and NibSymbol(systemName: "paintpalette"), falling back to .search and .plus. Suggest adding NibSymbol.eyedropper and NibSymbol.colourPicker.
- A ToolMenuDescriptor view cannot bud popovers. NibToolOptionsBar's droplet masks its content to the bar bounds plus 64 pt, and NibBudPopover must be a full-size child of the container, which the options-bar content cannot reach. So the thickness slider and the colour editor are inline modes of the same Clear bar, which re-forms around each row, not budded popovers. Suggest an options-bar popover hook, e.g. NibToolPalette(options:) returning a bar plus an optional popover.
- PresetSwatch.pattern is an AssetRef, but tape patterns are identified by TapePatternDescriptor.id. F008 stores the descriptor id as the AssetRef name ("builtin.dots"). F033 must resolve it through content.tapePatterns and copy the PNG into the document on use.
- CommandContext does not expose NibApp or content registries. preset.setSwatch checks tape pattern ids against NibApp.shared?.content.tapePatterns, and the check is skipped when NibApp.shared is nil.
- ToolPresets uses synthesized Codable, which is strict. A partial JSON written with settings.set (for example one missing 'patterns') fails to decode and silently falls back to the defaults. F008 normalises every state it reads (1-12 swatches, exactly 3 widths within bounds, one pattern per width, selections clamped), but cannot make decoding lenient.
- The eyedropper claims touches through CanvasAttachment.hitTest. With a finger in Pencil-only mode, it depends on F101's GestureRouter offering finger drags to attachments before the scroll view's pan.
- Contract request F008-pattern-swatch-and-symbols (could not be filed under docs/contract-requests/ because F008 does not own that path, so it is reported here): (1) NibDesign's NibPenSwatch needs a tape-pattern overlay, e.g. NibPenSwatch(pattern:), so FeatPresets can delete PatternSwatch in ColorSlotEditor.swift, which copies NibPenSwatch(.palette) metrics line for line; (2) NibSymbol needs .customColour ('paintpalette') and .eyedropper ('eyedropper') tokens to replace PresetSymbols, which currently goes through NibSymbol(systemName:). Both stand-ins have `ponytail:` comments pointing at this request.
- CommandContext cannot reach app.content, so a command cannot reach the content registries (tape patterns). Worked around with PresetSetSwatch.tapePatterns, an NSMapTable from CommandBus to Registry filled in FeatPresetsFeature.register. A ctx.content accessor in NibContracts would remove the workaround.

## F009
- shape.create's `frame` param format is not pinned down: ARCHITECTURE §6.1 says rects are [x,y,w,h], but ShapeItem's Frame is {x,y,w,h,rotation}. F009 sends [x,y,w,h] and turns a tilted box shape into a `polygon` of its outline, so the rotation is not lost. F031 has to accept the array form.
- shape.recognize's result shape is not pinned down ('ShapeItem JSON or null'; F030 also mentions mergeWith). F009 decodes a bare ShapeItem, {shape: ShapeItem, ...}, or null.
- Point semantics for arc/curve ShapeItems are undocumented. The live preview treats 3 points as a quadratic through the middle point. The committed shape passes the points through unchanged.
- The contracts don't say whether the canvas or the tool calls cancelWetStroke after strokeHeld returns true. F009 calls host.cancelWetStroke() itself, which assumes F101's cancel is idempotent.
- The contracts have no `name` for NibHighlighter colours and no highlighter translucency constant. F009 keeps its own localised names (Lemon to Blush). It stores picked colours at RGBA.highlighterYellow's alpha (0x80), the same alpha as the contract's default highlighter presets.
- The highlighter's Draw and Hold toggle is its own setting, `highlighter.drawAndHold` (default on). The pen uses `shapes.drawAndHold`, which another feature declares, and reading an undeclared typed key would fail conformance.
- Pen stabilisation EMA rule is not defined anywhere in the contracts or docs, and F007's Stabilizer.swift is still a scaffold placeholder. The highlighter uses its own rule: sample weight 1 - 0.85*amount, run forwards and backwards and averaged, with both endpoints kept. F007 should adopt the same rule, or say which one it uses, so the two tools match (spec: 'same EMA rule as pen').
- shape.create takes frame as [x,y,w,h], with no rotation. A Draw-and-Hold box that the pen has rotated is therefore sent as a 'polygon' with the four corner points, not as a rotated rectangle/ellipse. A rotated ellipse is sent as its 48-point polygon outline.

## F010
- The contracts cannot tell a tool when the dry tiles for newly committed items are on screen. The eraser keeps its preview for about 150 ms after ink.erase commits and then clears it and unhides. This is the same hand-off problem wet ink has (EraserTool.commit).
- CanvasTool.isSticky has no 'tool finished' signal. F016 would switch back to the previous tool without knowing when an erase finished, and a second switch could bounce back to the eraser. So the eraser always reports itself sticky and does Auto-deselect itself on lift through tool.select.
- The ink.erase catalogue row has no layer parameter, so the command uses ctx.activeSession?.activeLayer ?? 0, as the spec asks. An AI or bridge call with no window open erases on layer 0.
- CanvasHost cannot convert a sample from one page to another. An eraser gesture stays on the page it started on, and samples that land on other pages are ignored.
- NibStrokeWidthSlider is fixed to millimetres and a 'Thickness' label, so it does not fit an eraser measured in on-screen points. The size presets were built from NibColor, NibMetrics and NibPressStyle tokens. DESIGN.md asks for a 'destructive plain button', but NibButton has no such kind, so Clear Page uses NibButton .destructive.
- Dictionary(key:default:) cannot be used as a key path because of its autoclosure, so the sheet's switches bind to a Set through a small internal Set subscript(member:) extension in EraserSettingsView.swift.
- CanvasHost has no signal for when the renderer has drawn committed ink. So after its single ink.erase, EraserTool keeps its preview and hidden set for about 150 ms, then unhides. This avoids a flicker. A 'didRender(page:)' callback would replace the fixed delay.
- CanvasHost.setHidden can only hide whole items. While dragging, a cut stroke is hidden and what is left of it is redrawn in the tool overlay as a CAShapeLayer polyline (stroke colour, mid-point nib width, multiply blend for highlighter). There is no PencilKit ink look in that preview. A 'preview partial stroke' host API would make it exact.
- CanvasTool has no 'return to previous tool on lift' hook separate from isSticky. The eraser reports itself sticky and, when Auto-Deselect is on, runs tool.select with session.previousTool itself after the commit. That avoids a double bounce.
- The Delete Specific Items entry in the More menu opens the sheet through panel.open, which F017 owns. If F017 is disabled, that menu item fails with 'unavailable'.
- There is no query-API call for a synchronous snapshot of a page's items at touch-down. EraserTool reads app.workspace.items(doc, page:) directly for the live preview. The commit still goes through the ink.erase command.
- DocTransaction has no bulk or indexed tombstone. The fix now tombstones the items it already fetched, so tx.delete no longer does a second lookup. But tx.put still scans the page linearly (currentItem and writeItem), so page.clear, page.deleteItems and remove() stay quadratic on boards near NibLimits.boardItemLimit. The review asked for docs/contract-requests/F010-bulk-tombstone.md, but that path is not one of F010's files, so it was not written. The request is recorded here and in a ponytail comment in EraseSupport.remove.
- No spatial index is available to features. Stroke bounds are still computed point by point when the EraseSession is built. Touch-down now skips items outside session.visibleRect on the current page and computes bounds once per eligible item, but a real fix needs an indexed Workspace.items(in:).

## F011
- EditorSession.Selection holds only item ids and bounds, with no lasso outline polygon. The drawn outline lives in a per-session store inside FeatLasso (SelectionOutlines). After F012 moves or resizes the selection, the outline is mapped by scale and translate from the old item bounds to the new ones, so a rotated selection keeps an axis-aligned outline.
- Nothing guarantees that CanvasAttachment.canvasDidChange runs on selection changes (F006's spec lists only scroll, zoom, layout and commit). SelectionOverlay therefore also subscribes to session.$selection and bus.observeCommits.
- selection.fromLoop takes `stroke` as the item ref (or bare id) of an already-committed loop stroke. This is how the acceptance test reads it ('loop stroke restored'). F007 must commit the loop first, for example ink.addStrokes with a caller-chosen id, then pass that ref.
- There is no contract hook for a temporary tool switch. For quick selection and Circle to Lasso, the tool to return to is kept in session.toolOptions["lasso"].returnTool. It is restored when the selection is cleared and dropped once someone picks another tool (the second part is done by start() housekeeping).
- `lasso.include` is one synced key holding a [String] of categories, as the spec names it. This follows the precedent of NibSettings.experimental and pluginGalleries rather than the 'one key per entry' rule in ARCHITECTURE §15.5.
- There is no command or event to open the object menu. After a lasso closes, F011 only sets session.selection with its bounds, and F013 is expected to open MenuLocation.objectMenu when the selection becomes non-empty.
- ⌘A (select all), Esc and Delete are not registered here: F073 owns those KeyCommandDescriptors, and its test fails on duplicates. Key V comes only from the toolbar descriptor's `shortcut`, which F016 turns into a key command.
- Selection carries only item ids and bounds, with no lasso polygon. The drawn outline is kept in the module-local SelectionOutlines.bySession (keyed by session id), so plugins and the AI cannot read it. After a move or resize the overlay re-maps it by scale and translate only, so a rotated selection keeps an axis-aligned outline.
- There is no contract for a temporary lasso that hands back the previous tool (quick selection, Circle to Lasso). EditorSession.previousTool is overwritten on every tool switch, so the return tool is stored in session.toolOptions["lasso"]["returnTool"] and dropped when the user picks another tool (tool.changed event).
- The tap-handler params ({page, point, ref, gesture}) carry no zoom, so selection.tapAt converts its 8 pt finger tolerance to page points with session.zoom.
- Cmd+A and Esc belong to F073. KeyCommandDescriptor.params are static, so a Cmd+A mapping cannot pass the current page to selection.selectAll {page}. F073 or the shell needs a way to fill in the current page ref.
- The spec names lasso.include as one array-valued setting, but ARCHITECTURE section 15.5 prefers one key per entry for collections. It was kept as an array because the spec names it that way.
- There is no contract for 'this tool edits this item kind on tap'. selection.tapAt declines text boxes when session.tool == "text" by matching that tool id string, so the text tool can edit the box.

## F012
- The iOS 26 Liquid Glass `.droplet(style: .handle)` is SwiftUI-only and lives in the window's NibDropletContainer. A CanvasAttachment has no way to put a droplet on the canvas, so the handles are rigid CALayer beads drawn with NibDesign water tokens: Clear corners and rotation bead (clearBodyOnPaper or chromeOpaque, waterLine, CALayer.nibElevation(.rest)) and Tinted edges (accent, tintRim). They don't refract.
- The spec asks for a UIImpactFeedbackGenerator fallback, but Scripts/lint.py bans it in UI modules. Below iOS 17.5 the snap haptic is NibHaptics.play(.snap), which falls back to a soft impact generator itself. iOS 17.5+ uses UICanvasFeedbackGenerator(view:).alignmentOccurred(at:).
- CanvasAttachment gets a single touch stream with no multi-touch information. The two-finger drag-to-duplicate is a 2-touch UIPanGestureRecognizer added to host.canvasView. It only takes direct touches inside the selection, and it makes the canvas's pan and pinch recognizers wait for it only while a selection exists.
- KeyCommandDescriptor params are static, so the arrow keys can't name the selection. `refs` is optional in item.transform and item.moveToPage (the §6.5 catalogue lists it as required): when omitted it defaults to the invoking session's selection, and with nothing selected the command does nothing.
- There is no signal for when dry tiles have redrawn after a commit. The drag snapshot stays over the drop spot for 120 ms, then is removed.
- Attachments get no hover callbacks. Pointer hover shapes come from an invisible view that passes touches through: it answers hitTest only for .hover events over a handle and carries a UIPointerInteraction. The same view is the VoiceOver element for the selection.
- The item.duplicate (F014) result shape isn't in the contracts. The drag reads {"refs": [...]}, falling back to the caller-chosen `ids` it passed. selection.set (F011) may be missing; if so the session's selection is set directly.
- Frame.applying measures scale along page axes, which skews rotated boxes. item.transform still calls Item.transformed(by:), then overwrites boxed frames with TransformMath.frame, which measures along the frame's own axes.
- DocTransaction.put stamps createdBy on create for non-user principals. item.moveToPage re-puts items on the destination page, so an item moved there by the AI, a plugin or the bridge gets that principal's provenance.
- There's no shared live-transform state for F011's selection outline, so the outline doesn't follow a drag in progress. It catches up on commit; the F012 handles do follow the live preview.
- CanvasHost has no page-to-view transform. FeatTransform adds an internal CanvasHost.pageToView(_:) that builds the affine from three viewPoint probes, so zoom, page layout and rotation all count.
- Scripts/lint.py bans raw UIImpactFeedbackGenerator, so before iOS 17.5 the snap haptic uses NibHaptics.play(.snap), which falls back to UIImpactFeedbackGenerator internally. On iOS 17.5+ it uses UICanvasFeedbackGenerator.alignmentOccurred(at:) behind #available.
- No contract exposes a page template's grid spacing. GuideEngine.Grid reads it from the TemplateDefinition's rendered DisplayList (hlines/vlines/dots ops). If there are none it uses the template's 'spacing' param.
- item.duplicate (F014) has no typed contract beyond the catalogue entry {refs, offset?, ids?}. A drag-duplicate passes caller-chosen ids and an explicit [0,0] offset, then moves the copies with item.transform or item.moveToPage in the same undo group. If the result carries no 'refs', it falls back to refs built from the chosen ids.
- selection.set (F011) may not be installed. After a drop that creates or re-pages items, if selection.set fails, EditorSession.selection is set directly.
- NibError.Code.locked is meant for locked documents. Locked items are rejected as invalid_params, with a JSON path and a hint pointing at item.setLocked.

## F014
- There is no contract key for the text feature's default text style. Paste and Match Style reads the untyped setting 'text.defaultStyle', then 'text.styles.default' (TextBoxStyle or TextAttributes JSON), and falls back to TextBoxStyle(). F026 should confirm the name, or it should become a NibSettings constant.
- UTI 'app.nib.fragment' is not declared as an exported type in project.yml/Info.plist. It works as a raw type string for the pasteboard and for drags between Nib windows (NSItemProvider visibility .ownProcess), but it should be declared.
- clipboard.paste has an extra optional 'fragment' param (nib-fragment/1 JSON) beyond the catalogue's {page, at?, matchStyle?, ids?}. Canvas drops use it (images and text are converted to fragments, one undo step), and elements, plugins and the AI can use it too. The §6.5 catalogue row could list it.
- KeyCommandDescriptor params are static, so a shortcut cannot pass the selection or page. clipboard.copy, clipboard.cut and item.duplicate use the invoking window's selection when 'refs' is omitted (a silent no-op if nothing is selected); clipboard.paste uses the window's current page when 'page' is omitted. The schemas still mark refs and page as required, so other callers are still validated.
- A drag dropped back onto the same canvas moves the selection by calling F012's item.transform {refs, translate: [dx, dy]} (same page) or item.moveToPage {refs, page, offset: [dx, dy]} (other page). Those param shapes are assumed.
- Dropped files go to F064's import.files {urls: [file://…], doc: 'doc:D', position: 'after', anchor: 'page:D/P'}. The doc and anchor ref formats are assumed.
- UIDragInteraction does not expose allowedTouchTypes. Its lift recognisers are found by diffing canvasView.gestureRecognizers and limited to finger and pointer, so a Pencil held still keeps writing (Draw-and-Hold) instead of lifting the selection.
- The shell builds UIKeyCommands that call perform, not the responder 'paste:' action. iOS may therefore show its 'Allow Paste' prompt when ⌘V reads another app's content. A shell-level paste: responder or UIPasteControl would avoid it.
- No shared pasteboard service in the contracts, so FeatClipboard has its own internal seam (ClipboardBoard protocol, UIPasteboard.general in the app, an in-memory board in tests).
- There is no contract for the user's default text style, so Paste and Match Style reads the settings keys 'text.defaultStyle' / 'text.styles.default' (as TextBoxStyle or TextAttributes JSON) and falls back to TextBoxStyle() when neither is set. The text feature has to save its default style under one of those keys.
- 'selection.clear' has no constant in CommandIDs, so it is called by its string literal. selection.set, item.transform, item.moveToPage, import.files and recognize.items use their CommandIDs constants.
- import.files 'position'/'anchor' values are not pinned down anywhere, so dropped files are sent as {urls, doc: doc ref, position: "after", anchor: page ref}, the same shape page.add uses.
- UIDragInteraction has no API to keep Apple Pencil from lifting a drag, so on attach the drag interaction's own gesture recognisers are found by diffing the view's recognisers and restricted to finger and pointer touches. This keeps Draw-and-Hold working with the Pencil.
- NibSymbol has no paste glyph. The Paste and Match Style long-press menu entry now uses icon: nil. The contract request (docs/contract-requests/F014-paste-symbol.md) was not filed because that path is not in F014's owned files.
- There is no stroke or border-width design token, so the drop highlight border uses NibSpacing.xxs (2 pt).

## F015
- ToolbarItemDescriptor.params and KeyCommandDescriptor.params are static JSON, but edit.undo and edit.redo require `doc`. Nothing injects the invoking session's document: the shell's runKeyCommand passes d.params as they are. Workaround in UndoButtons.swift: UndoChrome re-registers the toolbar items and key commands with {doc: <key-window or active session's document>} whenever there is a commit, undo, redo, session.document / doc.opened / doc.closed event, a change to editing.undoOnRight, or UIWindow.didBecomeKey. Unchanged state registers nothing. Requested fix: the shell and toolbar fill `doc` from the invoking session when a command's schema requires it and params omit it, or edit.undo / edit.redo fall back to ctx.activeSession?.document.
- ToolbarItemDescriptor has no enabled or disabled state, so the Undo and Redo buttons cannot grey out when canUndo or canRedo is false. They carry the step label from bus.history.undoLabel / redoLabel in the title instead ('Undo Add Page', or plain 'Undo').
- Only the canvas editor view controller (F006) or the shell can override UIResponder.editingInteractionConfiguration. Workaround in UndoGestures.swift: an invisible UndoFocusResponder view inside canvasView overrides it to return .none. It takes first responder when it appears and on any direct finger touch on the canvas, but never while session.isEditingText is true. Requested fix: DocumentEditing editors or the shell return .none, which makes this responder unnecessary.
- SessionRegistry.activate(_:) emits no event, so a window switch cannot be observed. Workaround: UndoChrome listens for UIWindow.didBecomeKeyNotification and picks the session whose editor view is in the key window.
- NibBadge has no principal (provenance) kind. The History row's badge is built from tokens only: caption2 text plus a NibSymbol glyph on a fill3 capsule, styled like NibBadge(.plugin).
- F015 registers no new commands. Every action runs an existing contract command (edit.undo, edit.redo, history.list, history.revertGroup, settings.set), so CommandConformance has nothing extra to check.
- ToolbarItemDescriptor has no size-class hint. DESIGN.md's iPhone trailing bar shows only Undo, Assistant and More, so the document chrome or toolbar owner has to drop redo.undo on compact width.
- ToolbarItemDescriptor and KeyCommandDescriptor params and titles are static. To keep the doc param and the 'Undo <label>' titles current, UndoChrome re-registers both descriptors on each commit, document change, key-window change or undoButtonsOnRight change. It skips the re-register when nothing changed. A per-session params/title closure in the contract would remove this.
- There is no contract hook to set editingInteractionConfiguration on the canvas editor's view controller. The workaround is an invisible UndoFocusResponder (returns .none) inside the canvas that takes first responder when the canvas appears or a finger touches it.
- history.list never returns sync principals, because remote merges are not recorded for undo. So the collaborator badge is mapped but, with the current contract, never shown.
- NibDesign NibBadgeKind has no 'principal' case (You/Assistant/Plugin/Bridge/Collaborator with glyph). PrincipalBadge in NibKit/Sources/FeatUndoUI/HistoryPanel.swift is still built locally. Its literal 20 pt height is now NibSpacing.xxs vertical padding, so it uses tokens only. Request: add a principal case to NibBadgeKind so HistoryPanel can use NibBadge instead.

## F051
- ExporterDescriptor has no document-kind filter, so F067's Share & Export dialog cannot tell that exporter "study.csv" only applies to study sets. For any other kind the handler throws invalid_params. Suggested fix: an optional `docKinds: Set<DocumentKind>` on ExporterDescriptor.
- The ImporterDescriptor handler receives only a local URL and an ImportTarget. It gets no caller-chosen id (import.files `ids?`) and no original display name. New sets imported through import.files get generated ids, and a tmp: or downloaded file is titled from its local filename. I strip the '<UUID>-' prefix that inputFile adds to https downloads, but a tmp: asset still gets its hash name. study.importText itself honours `id` and titles sets from the original url.
- FractionalIndex.sequence grows keys by about one character every 6 keys, which is unusable for a 10,000-card deck. I worked around it locally: StudyImport.orderKeys builds balanced keys by bisection with FractionalIndex.between, at most 3 characters for 10k cards.
- Workspace.writeRecord copies the whole card array on every tx.put, so appending N cards to an existing set costs O(N²). New sets avoid this by being built whole and written with LibraryService.createDocument. Only the importer path that appends into an existing study set pays it.

## F052
- The recording HUD and the playback bar have no chrome extension point. DESIGN.md §14.13 wants a Clear recording HUD budded to top centre and a Clear audio bar at bottom centre, but contracts have no floating-HUD or bar registry. Workaround: the recorder (dot, clock, live waveform, Pause/Stop) and the playback bar live in the Audio sidebar tab, as the forge spec says. The recording indicator is the toolbar accessory (turns into Stop) plus the tab icon and title ('Recording').
- NibSymbol has no tokens for the record dot ('record.circle') or the ±10 s glyphs ('gobackward.10' / 'goforward.10'). Workaround: names are checked with NibSymbol(systemName:) and fall back to .microphone / .back / .forward.
- There is no playback-time service for F053 Note Replay. Workaround: every play/pause/seek/re-plan emits an 'audio.playback' event {clip, t, playing, rate, at}, and audio.setPlayback {} returns the live PlaybackStatus (clip, t, duration, playing, speed, skipSilence, noiseReduction). Recording emits 'audio.recording' {clip, state, duration}.
- Nothing in the contracts guards AudioClip.file, so a synced or AI-edited record could point outside its package. Workaround: AudioRefs.fileURL refuses '..' and absolute paths with invariant_violation before play, export or delete touches the file (tested).
- NibSymbol has no record-dot token for the recording indicator. FeatAudioFeature.swift works around it with NibSymbol(systemName: "record.circle") ?? .microphone. This gap was noted in the code; it did not come from CI.

## F055
- TextRecognizer / TextRecognition are line-level only, with no word boxes. recognize.items needs {words:[{text,bbox,refs}]}, so NibIndex casts services.recognizer to its own VisionRecognizer to get real Vision word boxes. Any other recognizer (FakeRecognizer, or one a plugin supplies) gets proportional word splitting instead. A future contract could add `words` to TextRecognition.
- NibEventType has no constant for indexing progress. NibIndex emits the string "index.progress" with payload {running, done, total, pending}. F056's 'Indexing N pages…' banner has to match that literal until a shared constant is added.
- The 'nib.scanText' page ext has no shared type or constant. F055 accepts [TextRecognition], a list of {text, bbox?, alternatives?, itemIDs?, confidence?}, {blocks:[…]}, or a plain string. F065 should write [TextRecognition].
- No contract for transcript file discovery or merging. F055 re-implements F054's rule (legacy <base>.json plus <base>.<8hex>.json, highest rev per index wins) via persistence.fileURL. Transcript edits make no commits, so the document version also includes the transcript files' modification times.
- There is no shared hook for 'library title changed'. Title units refresh on NibEventType.libraryChanged events, so this relies on F002 emitting library.changed on rename, move, trash and delete.

## F058
- NibSymbol has no glyphs for straighten, align left/centre/right, insert space, cut, paste, colour palette or edit handwriting. The workaround uses NibSymbol(systemName:) with a NibSymbol fallback (SmartInkSymbol in EditHandwritingMode.swift), and the toolbar, menu and settings descriptors use the icon strings 'scribble', 'level' and 'arrow.up.and.down'.
- CommandIDs has no constants for clipboard.cut or item.recolor, so string ids are used. Word recolour, cut and delete (F013/F014) and the paste repositioning via item.transform (F012) are cross-feature calls by id. Only the item.transform step during paste is quiet if its feature is missing; failures of the others go to the shell's toast.
- content.tapHandlers can only route to a command, and F058 owns only the five handwriting.* ids. Double-tap word selection is therefore handled inside the Edit Handwriting tool (smartink.edit, entered via tool.select from the object menu or the More grid), not as a canvas-wide tap handler.
- The options bar needs a palette slot to fuse to (NibToolPalette only shows options for a tool on the palette). F058 registers a ToolbarItemDescriptor for smartink.edit in .tools (order 900) so a tool entered from the object menu still has an anchor. F016 decides where it shows.
- Nothing in the contracts guarantees whether the lasso clears its selection before or after the next tool activates. EditHandwritingModel keeps the last non-empty selection for 1.5 s so the tool still picks it up either way.
- Auto-straighten (S-037) uses NibHaptics.isInking, which DropletField sets from NibInkingState, to hold off while the Pencil is down. There is no non-UI canvas signal for 'Pencil down'.
- Tests have no public way to insert items without F003/F007, so tests write synthetic strokes into InMemoryPersistence.pageItems before first load. The auto-straighten test registers a stand-in ink.addStrokes command inside the test.

## F062
- recognize.items only takes refs of strokes already stored in a document. The handwriting pad's strokes are temporary, so they go to services.recognizer (the TextRecognizer behind recognize.items) through PKBridge.stroke and Item.makeStroke. A read command that takes inline strokes would close this gap.
- A canvas attachment cannot reach the document chrome's NibDropletContainer. The bar is therefore a lone .nibGlass(.clear) HUD, hosted in the canvas's superview. It has no merge or stretch physics and no palette-aware docking: it sits at bottom centre, 16 pt above the safe area, or 80 pt up on iPhone to clear the palette. A chrome HUD slot or registry would fix this.
- The design system has no public input to tell nibGlass the Pencil is down (the internal nibIsInking environment value). So while writing, the bar swaps glass for a plain NibColor.clearBody fill, the same thing the container draws for frozen droplets. It notices the Pencil through NibHaptics.isInking plus CanvasAttachment.hitTest, because NibInkingState is not reachable from a canvas attachment.
- NibProgressBar has no critical or tint option. The bar that turns red in the last 5 s (TimeKeeperProgress) is built locally from the same tokens (3 pt fill1 track, label/destructive fill).
- NibSymbol has no timer, stopwatch or flag glyphs. The code uses the public NibSymbol(systemName:) with fallbacks to .recents and .bookmark. The descriptor icon string is "timer".
- panel.open takes no instant or no-bud flag, so opening the panel from the K key cannot ask the host to skip the bud animation (DESIGN.md §9.3).
- ToolbarItemDescriptor has no on or active state, so the accessory cannot show that a session is running.

## F063
- The chrome's NibDropletContainer has no slot for a feature HUD. The DESIGN §14.12 presenter HUD is hosted as a CanvasAttachment ('presentation.hud') using static `nibGlass(.clear)`, so it does not merge with other droplets or recede to 22% while the Pencil is down.
- There is no pure-black token for the external display letterbox. The presentation VC sets overrideUserInterfaceStyle = .dark and uses NibUIColor.desk, which resolves to about #121214.
- The contracts expose no inking state (NibInkingState belongs to the canvas). Mirror snapshots (drawHierarchy on main, adaptive to at most about 20% of the main thread) therefore cannot pause while the Pencil is down.
- There is no API for an external display's name. It is read from the AVAudioSession route (the AirPlay/HDMI portName), falling back to 'External Display'.
- SessionRegistry.active is not observable. The live source re-reads it on UIScene.didActivateNotification and lazily on every read.
- MenuItemDescriptor has no checked state. Each mode registers two Share & Export entries (plain, and checked with the checkmark icon), and isVisible shows one of them.
- KeyCommandDescriptor params are static, so a Blank toggle shortcut cannot be expressed without adding a toggle param to present.setMode. No key commands were registered. The HUD buttons are focusable (Full Keyboard Access), have pointer hover, and the laser keeps its own tool key (F040).
- The CanvasAttachment docs do not say whether canvasView is the scroll view or its zoomed content. The HUD is positioned in canvasView.bounds and safeAreaInsets on every canvasDidChange, which assumes the scroll view.

## F090
- F091 (Bridge settings UI) cannot import NibBridge, so it has to reach several bridge details by literal names that exist only in this module. Keychain token: service "app.nib.bridge", account "token". Settings: security.bridge.enabled, security.bridge.port (default 7331), security.bridge.networks (CIDR list) and security.bridge.origins. Status event "bridge.status", emitted on app.events. Token rotation goes through bridge.setEnabled {enabled: true, rotateToken: true}. The contracts have no shared constants for any of these.
- The bridge's confirmation deadline (unanswered confirmations for .bridge principals are denied after 115 s, so no request waits more than 120 s) works by wrapping app.gateway.presenter in register(). This only holds if no later feature replaces gateway.presenter without delegating to the one it replaces. The contracts have no per-principal confirmation-timeout hook.
- Gateway.policy has no per-principal registration API. The bridge chains onto the existing closure so that .bridge principals follow NibSettings.bridgeConfirmationPolicy. A feature that later overwrites gateway.policy without chaining would drop that.
- The 'ai.directTools' setting (F084) is read untyped with settings.json("ai.directTools"). When it is absent, the bridge uses the default direct-tool list from AI.md §4, copied into MCPHandler.defaultDirectTools. The contracts do not export that default list.
